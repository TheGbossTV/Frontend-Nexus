## Introduction

Redux Toolkit (RTK) is the official, opinionated toolset for Redux, maintained
by the Redux team. Current major version: **v2** (2.12.x at the time of
writing), paired with **react-redux v9** for the React bindings.

It exists because classic Redux was correct but exhausting: action type
constants, hand-written action creators, switch-statement reducers, and manual
immutable updates spread across several files for a single feature. RTK collapses
all of that into `createSlice`, and it is now the approach the Redux docs teach
by default — plain `createStore` is deprecated in its favour.

Two things do most of the work. `configureStore` sets up the store with good
defaults already applied: your reducers combined, the thunk middleware included,
development-only checks for accidental mutation and non-serialisable values, and
the Redux DevTools connected. `createSlice` generates the action types, action
creators, and reducer from one object.

## Immer, and why reducers look like they mutate

RTK bundles [Immer](https://immerjs.github.io/immer/), so reducer code that
looks like it mutates state is safe:

```js
reducers: {
  increment: (state) => {
    state.value += 1
  },
}
```

`state` here is a draft proxy. Immer records what you touched and produces a new
immutable state from it, so you get the readability of mutation with the
guarantees of immutability. The one rule: either mutate the draft *or* return a
brand-new value — never both in the same reducer.

## RTK Query

RTK Query is included in the same package rather than being a separate install.
It's a data-fetching and caching layer built on top of the store, so if you're
already running Redux it usually removes the need for a second server-state
library. It generates hooks, de-dupes identical requests across components, and
handles cache lifetimes for you.

## Quick Reference

Everything below is exported from `@reduxjs/toolkit`, except the two hooks marked
`react-redux` and the RTK Query entry points, which come from
`@reduxjs/toolkit/query/react`.

- `configureStore(options)` — creates the store with thunk, dev-time checks, and DevTools already wired.
- `createSlice(options)` — generates action types, action creators, and a reducer from one object.
- `slice.reducer` — the generated reducer, handed to `configureStore`'s `reducer` map.
- `slice.actions` — the generated action creators, one per key in `reducers`.
- `slice.selectors` — selectors declared on the slice, pre-scoped to its slot in the store.
- `useSelector(selector)` — from `react-redux`; subscribes a component to a slice of state.
- `useDispatch()` — from `react-redux`; returns the store's `dispatch`.
- `createAsyncThunk(type, payloadCreator)` — wraps an async call, dispatching `pending`/`fulfilled`/`rejected` for you.
- `createSelector(inputs, resultFn)` — memoises derived state so it isn't recomputed on every render.
- `createEntityAdapter(options)` — normalised CRUD helpers plus `getSelectors` for a collection.
- `createAction(type)` — a standalone action creator, for actions no single slice owns.
- `createReducer(initialState, builder)` — a reducer without a slice, using the same Immer drafts.
- `combineSlices(...slices)` — combines slices into one reducer, with lazy `injectInto` for code splitting.
- `createListenerMiddleware()` — runs side effects in response to actions, without a thunk.
- `getDefaultMiddleware()` — the default middleware array, for adding to rather than replacing.
- `isAnyOf(...matchers)` / `isAllOf(...)` — action matchers for `extraReducers` and listeners.
- `current(draft)` — a plain snapshot of an Immer draft, for logging mid-reducer.
- `nanoid()` — the id generator RTK uses internally, exported for your own ids.
- `createApi(options)` — defines an RTK Query API slice and generates a hook per endpoint.
- `fetchBaseQuery(options)` — a small `fetch` wrapper used as an API's `baseQuery`.
- `setupListeners(dispatch)` — enables refetch-on-focus and refetch-on-reconnect.

<Level value="easy">

A slice bundles the state, the action types, and the reducer logic together:

```js
import { createSlice } from '@reduxjs/toolkit'

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: (state) => {
      state.value += 1
    },
    incrementBy: (state, action) => {
      state.value += action.payload
    },
    reset: () => ({ value: 0 }),
  },
})

export const { increment, incrementBy, reset } = counterSlice.actions
export default counterSlice.reducer
```

`configureStore` wires the slice reducers together:

```js
import { configureStore } from '@reduxjs/toolkit'
import counterReducer from './counterSlice'

export const store = configureStore({
  reducer: {
    counter: counterReducer,
  },
})
```

Unlike Zustand, Redux does need a provider at the root:

```jsx
import { Provider } from 'react-redux'
import { store } from './store'

createRoot(document.getElementById('root')).render(
  <Provider store={store}>
    <App />
  </Provider>,
)
```

Components read with a selector and write by dispatching an action:

```jsx
import { useDispatch, useSelector } from 'react-redux'
import { increment } from './counterSlice'

function Counter() {
  const value = useSelector((state) => state.counter.value)
  const dispatch = useDispatch()

  return <button onClick={() => dispatch(increment())}>Count: {value}</button>
}
```

<Level value="medium">

**Type the store once, then use pre-typed hooks everywhere.** Deriving the types
from the store means they can never drift from the real shape:

```ts
// store.ts
export const store = configureStore({
  reducer: { counter: counterReducer },
})

export type RootState = ReturnType<typeof store.getState>
export type AppDispatch = typeof store.dispatch
```

```ts
// hooks.ts
import { useDispatch, useSelector } from 'react-redux'
import type { AppDispatch, RootState } from './store'

export const useAppDispatch = useDispatch.withTypes<AppDispatch>()
export const useAppSelector = useSelector.withTypes<RootState>()
```

`withTypes` is the current recommendation in react-redux 9 — it replaces the
older habit of hand-writing `useSelector: TypedUseSelectorHook<RootState>`. Use
`useAppSelector` and `useAppDispatch` in components from then on; the plain hooks
won't know about your thunk middleware.

**Async work goes through `createAsyncThunk`**, which dispatches
pending/fulfilled/rejected actions for you:

```ts
import { createAsyncThunk, createSlice } from '@reduxjs/toolkit'

export const fetchUser = createAsyncThunk(
  'users/fetchById',
  async (userId: string) => {
    const response = await fetch(`/api/users/${userId}`)
    return response.json()
  },
)

const usersSlice = createSlice({
  name: 'users',
  initialState: { entity: null, loading: false },
  reducers: {},
  extraReducers: (builder) => {
    builder
      .addCase(fetchUser.pending, (state) => {
        state.loading = true
      })
      .addCase(fetchUser.fulfilled, (state, action) => {
        state.loading = false
        state.entity = action.payload
      })
  },
})
```

Note `extraReducers` uses the builder callback — the object form was removed in
RTK 2.

**Derive rather than duplicate.** `createSelector` memoises, so a computed value
isn't recalculated on unrelated state changes:

```ts
import { createSelector } from '@reduxjs/toolkit'

const selectTodos = (state: RootState) => state.todos.items

export const selectDoneCount = createSelector(
  [selectTodos],
  (todos) => todos.filter((todo) => todo.done).length,
)
```

</Level>

<Level value="advanced">

**RTK Query replaces most hand-written fetching code.** Define the endpoints
once and you get hooks, caching, de-duplication, and loading state:

```ts
import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react'

export const api = createApi({
  reducerPath: 'api',
  baseQuery: fetchBaseQuery({ baseUrl: '/api/' }),
  tagTypes: ['Todo'],
  endpoints: (builder) => ({
    getTodos: builder.query({
      query: () => 'todos',
      providesTags: ['Todo'],
    }),
    addTodo: builder.mutation({
      query: (body) => ({ url: 'todos', method: 'POST', body }),
      // Refetches anything providing 'Todo' — no manual cache juggling.
      invalidatesTags: ['Todo'],
    }),
  }),
})

export const { useGetTodosQuery, useAddTodoMutation } = api
```

It needs its reducer *and* its middleware registered:

```ts
export const store = configureStore({
  reducer: { [api.reducerPath]: api.reducer },
  middleware: (getDefaultMiddleware) =>
    getDefaultMiddleware().concat(api.middleware),
})
```

The `providesTags` / `invalidatesTags` pairing is the part worth internalising:
a mutation declares what it invalidated, and every query providing that tag
refetches. You describe relationships instead of imperatively clearing caches.

**Side effects without thunks.** The listener middleware reacts to dispatched
actions, which suits "when X happens, also do Y" logic that doesn't belong in a
component:

```ts
import { createListenerMiddleware } from '@reduxjs/toolkit'

const listenerMiddleware = createListenerMiddleware()

listenerMiddleware.startListening({
  actionCreator: settingsChanged,
  effect: async (action, listenerApi) => {
    localStorage.setItem('settings', JSON.stringify(action.payload))
  },
})

const store = configureStore({
  reducer: rootReducer,
  middleware: (getDefaultMiddleware) =>
    // prepend, not concat — it can receive actions containing functions, so it
    // has to run before the serializability check.
    getDefaultMiddleware().prepend(listenerMiddleware.middleware),
})
```

**Normalise collections with `createEntityAdapter`.** Storing a list as an array
means every lookup is a scan and every update rewrites the array. The adapter
keeps `{ ids, entities }` and gives you sorted selectors for free:

```ts
import { createEntityAdapter, createSlice } from '@reduxjs/toolkit'

const todosAdapter = createEntityAdapter({
  sortComparer: (a, b) => a.title.localeCompare(b.title),
})

const todosSlice = createSlice({
  name: 'todos',
  initialState: todosAdapter.getInitialState(),
  reducers: {
    todoAdded: todosAdapter.addOne,
    todosReceived: todosAdapter.setAll,
    todoRemoved: todosAdapter.removeOne,
  },
})

export const { selectAll: selectAllTodos, selectById: selectTodoById } =
  todosAdapter.getSelectors((state) => state.todos)
```

## Introduction

`fetch` is a web platform API, not a library — there's no version to track and
nothing to install. It's available in every current browser, and **global in
Node since v18**, so the same code runs in both. `Headers`, `Request`,
`Response`, `FormData`, and `AbortController` come with it.

```js
const response = await fetch('/api/todos')
const todos = await response.json()
```

Two design decisions surprise nearly everyone coming from older HTTP libraries,
and both are deliberate.

## It does not reject on HTTP errors

A `fetch` promise rejects only when the request genuinely *fails* — network
down, DNS failure, malformed URL, CORS block. A response of 404 or 500 is a
successful round trip as far as fetch is concerned, so the promise resolves
normally:

```js
const response = await fetch('/api/missing')
// No throw. response.ok === false, response.status === 404
```

This is the single most common bug in hand-written fetch code. Without an
explicit check, the error page's body gets parsed as your data:

```js
if (!response.ok) {
  throw new Error(`HTTP ${response.status}`)
}
```

Every wrapper library that "throws on errors" is just doing this for you.

## The body can only be read once

A `Response` body is a stream, so `json()`, `text()`, and `blob()` each consume
it. Calling two of them on the same response throws:

```js
const data = await response.json()
const text = await response.text() // TypeError: body already read
```

If you need it twice — logging a failed response before throwing, say — call
`response.clone()` first, or read it once as text and parse it yourself.

## Quick Reference

All globals — nothing to import, in browsers or in Node 18+.

- `fetch(input, init?)` — makes the request; `input` is a URL string or a `Request`.
- `response.ok` — `true` only for status 200–299, and the check fetch will never do for you.
- `response.status` / `response.statusText` — the numeric code and its message.
- `response.json()` — parses the body as JSON; consumes the stream.
- `response.text()` — reads the body as a string.
- `response.blob()` — reads the body as a `Blob`, for files and images.
- `response.arrayBuffer()` — reads the body as raw bytes.
- `response.formData()` — reads a multipart or urlencoded body back as `FormData`.
- `response.clone()` — copies the response so the body can be read a second time.
- `response.headers.get(name)` — reads one response header, case-insensitively.
- `response.body` — the raw `ReadableStream`, for consuming a response progressively.
- `Headers` — builds request headers; also `set`, `append`, `has`, and iteration.
- `Request(url, init)` — a reusable request object, handy for interceptor-style wrappers.
- `Response(body, init)` — constructs a response by hand, for tests and service workers.
- `Response.json(data, init?)` — static shortcut that builds a JSON response.
- `AbortController` — created per request; its `abort()` cancels the fetch.
- `controller.signal` — passed as `init.signal` to make the request cancellable.
- `AbortSignal.timeout(ms)` — a signal that aborts itself, replacing hand-rolled timeout races.
- `AbortSignal.any([…])` — aborts as soon as any of several signals does, e.g. timeout *or* unmount.
- `FormData` — multipart bodies; pass it directly and let the browser set the boundary header.
- `URLSearchParams` — builds urlencoded bodies and query strings with correct escaping.

<Level value="easy">

A GET request, with the status check that fetch won't do for you:

```js
async function getTodos() {
  const response = await fetch('/api/todos')

  if (!response.ok) {
    throw new Error(`Failed to load todos: ${response.status}`)
  }

  return response.json()
}
```

Sending JSON requires both the body and the header — fetch won't infer the
content type:

```js
const response = await fetch('/api/todos', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ title: 'Buy milk' }),
})
```

Build query strings with `URLSearchParams` rather than concatenating, so
encoding is handled for you:

```js
const params = new URLSearchParams({ status: 'open', page: '2' })
const response = await fetch(`/api/todos?${params}`)
```

Reading the response depends on what it is:

```js
await response.json()  // parsed JSON
await response.text()  // raw string
await response.blob()  // binary, e.g. an image
```

</Level>

<Level value="medium">

**Cancel requests with `AbortController`.** This matters in React: without it, a
response arriving after the component unmounts sets state on nothing, and two
rapid requests can resolve out of order:

```js
const controller = new AbortController()

fetch('/api/search?q=react', { signal: controller.signal })

controller.abort() // cancels it
```

```jsx
useEffect(() => {
  const controller = new AbortController()

  fetch(`/api/search?q=${query}`, { signal: controller.signal })
    .then((r) => r.json())
    .then(setResults)
    .catch((error) => {
      if (error.name !== 'AbortError') throw error
    })

  return () => controller.abort()
}, [query])
```

**Timeouts have a built-in shortcut.** `AbortSignal.timeout()` saves wiring a
timer to a controller:

```js
const response = await fetch('/api/slow', {
  signal: AbortSignal.timeout(5000),
})
```

One detail worth knowing: a timeout rejects with a **`TimeoutError`**, not an
`AbortError`. Code that only checks for `AbortError` will treat a timeout as an
unexpected failure:

```js
try {
  await fetch(url, { signal: AbortSignal.timeout(5000) })
} catch (error) {
  if (error.name === 'TimeoutError') { /* took too long */ }
  if (error.name === 'AbortError')   { /* we cancelled it */ }
}
```

**File uploads use `FormData`.** Do *not* set `Content-Type` yourself here — the
browser must generate it, because it includes the multipart boundary:

```js
const form = new FormData()
form.append('avatar', fileInput.files[0])

await fetch('/api/avatar', { method: 'POST', body: form })
```

**Cookies need opting in** for cross-origin requests:

```js
fetch('https://api.example.com/me', { credentials: 'include' })
```

**A small wrapper removes the repetition** without taking on a dependency:

```js
async function api(path, options = {}) {
  const response = await fetch(path, {
    ...options,
    headers: { 'Content-Type': 'application/json', ...options.headers },
  })

  if (!response.ok) {
    const body = await response.text()
    throw new Error(`HTTP ${response.status}: ${body}`)
  }

  return response.status === 204 ? null : response.json()
}
```

The 204 check matters — a No Content response has an empty body, and calling
`json()` on it throws.

</Level>

<Level value="advanced">

**Combine cancellation reasons with `AbortSignal.any()`.** Useful when a request
should stop either on timeout *or* because the user navigated away:

```js
const controller = new AbortController()

const response = await fetch(url, {
  signal: AbortSignal.any([controller.signal, AbortSignal.timeout(5000)]),
})
```

The resulting signal aborts as soon as any input does, and `signal.reason`
tells you which.

**Stream a response** instead of buffering it, for large payloads or progressive
rendering:

```js
const response = await fetch('/api/export')
const reader = response.body.getReader()
const decoder = new TextDecoder()

while (true) {
  const { done, value } = await reader.read()
  if (done) break
  process(decoder.decode(value, { stream: true }))
}
```

`response.body` is a `ReadableStream`, which is also how you'd track download
progress — compare bytes read against the `Content-Length` header.

**Retry with backoff**, but only for things worth retrying. Retrying a 400 just
fails more slowly:

```js
async function fetchWithRetry(url, options, attempts = 3) {
  for (let attempt = 0; attempt < attempts; attempt++) {
    try {
      const response = await fetch(url, options)
      // Retry server errors and rate limits, not client mistakes.
      if (response.status >= 500 || response.status === 429) {
        throw new Error(`HTTP ${response.status}`)
      }
      return response
    } catch (error) {
      if (error.name === 'AbortError') throw error // honour cancellation
      if (attempt === attempts - 1) throw error
      await new Promise((resolve) => setTimeout(resolve, 2 ** attempt * 200))
    }
  }
}
```

**`Request` and `Response` are constructible**, which is what makes service
workers, mocking, and framework route handlers work the way they do:

```js
const request = new Request('/api/todos', { method: 'POST', body: '{}' })
const response = Response.json({ ok: true }, { status: 201 })
```

`Response.json()` as a *static* method builds a JSON response — distinct from
`response.json()`, which reads one.

**Send data during page unload** with `keepalive`, since a normal fetch is
cancelled when the document goes away:

```js
fetch('/api/analytics', {
  method: 'POST',
  body: JSON.stringify(event),
  keepalive: true,
})
```

There's a small payload limit (around 64 KB across all keepalive requests), so
this is for beacons, not uploads.

**Know your error taxonomy**, because they need different handling:

- `TypeError` — network failure, CORS rejection, or bad arguments. The request
  never completed.
- `AbortError` — you cancelled it.
- `TimeoutError` — `AbortSignal.timeout()` fired.
- No error at all — the request completed; check `response.ok` yourself.

</Level>
